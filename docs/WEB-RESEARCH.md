# Read public pages and JSON

Current deployment identities are recorded in [staging acceptance](STAGING.md) and [operations](OPERATIONS-20261010.md). The reader and JSON verification counts/pins below belong to their named historical candidates. The public reader remains enabled on staging; the separate GitHub connector is implemented but unconfigured and awaits real acceptance.

This is the first host-mediated web capability for OpenClaw-backed Agent NFTs. It answers a question about one to three public HTTPS pages or JSON API endpoints explicitly supplied by the signed holder. For example, a holder can supply a public GitHub repository or releases API URL. Sources must require no login, API key or access token. It does not discover sources through web search or grant arbitrary OpenClaw tools, shell access or connected-account permissions.

The backend flag `JEFF_WEB_RESEARCH_ENABLED=true` enables the capability when a model is configured and storage is not restore-guarded. The default is disabled. The UI reads actual availability from `/api/config`, preserves the question and URLs after failure, and requires fresh consent for every submitted attempt. A request whose admission is uncertain requires deliberate Activity review before retry.

Consent is part of the signed manual job request, scoped by the existing NFT/holder/ownership-epoch session. The endpoint accepts `research: { urls: [...], consent: true }`. Research is rejected on scheduled submissions. A manual research run cannot authorize recurring reads. Hosting, pause, concurrency, inference admission, Stop, maintenance and ownership checks remain in effect. An admitted failed retrieval consumes the normal task allowance; no provider call is made if every page fails.

The host reads each supplied URL with native HTTPS, pins a checked public IPv4 address, and sends no cookies, bearer tokens or model credentials. Private, link-local, shared, documentation, multicast/reserved addresses, IP-literal URLs, alternate ports, embedded credentials, redirects, unsupported bodies and compressed bodies are rejected. Supported types are HTML, XHTML, plain text, application/json and application/*+json. IPv6-only sources are unavailable in this slice. Per-source limits are eight seconds, 128 KiB received and 2,400 excerpt characters. HTML text extraction is deliberately simple; it is not a browser or a full-page/archive reader.

JSON requires valid UTF-8 and syntactically valid JSON with at most 64 structural nesting levels. Its original text is retained rather than reserialized, preserving large integer and decimal spellings and literal field text. Invalid JSON fails that source with a fixed error code. The excerpt may end before the dataset ends or be incomplete JSON; truncation is labeled. API pagination, linked resources, credentials and account actions are not followed or granted. JSON fields remain untrusted evidence and cannot authorize memory, schedules or tools. This is public API reading, not an authenticated connected-account integration.

Ownership is rechecked before retrieval, after retrieval and before the result returns. Page text is untrusted evidence in the model context. OpenClaw's own tools remain denied. Research runs bypass all memory/schedule action decoding, including direct-memory requests. Stop aborts both DNS waiting and active HTTP work before the model, or the runtime child after it starts.

The host appends authoritative supplied URLs, retrieval timestamps and excerpt coverage to the same durable saved result. Model-created Markdown links/images are converted to prose using the same lexer as the UI; numbered citations are linked only to retrieved host sources. These links establish which pages were retrieved, not automatic verification that every generated claim is supported. Partial coverage is explicit; zero retrieved pages fail the run. Reloading a result does not fetch pages or call the model again.

Verification includes unsafe/mixed DNS, address pinning, redirect/content/body limits, Stop during DNS/HTTP, consent and schedule rejection, ownership transfer, action-envelope suppression, saved-result restart, seven adversarial cases against the actual Markdown renderer, and six integrated browser checks using real HTTPS pages with a simulated model.
